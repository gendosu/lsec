# ストア操作の排他

公開 API の同期性と version 1 の形式を維持するため、`SecretStore` の操作境界で `withStoreLock` を使う。`get` はロックを持つ `tryGet` に委譲する。内部の crypto / store-file ヘルパーは単独のトランザクションを作らず、呼び出し元が排他を管理する。

- `.lsec.lock` の非再帰 `mkdirSync` の成功で所有権を取得する。存在確認と作成を分離しない。同じ実体ディレクトリへの別名パスは同じロックに競合する。
- 復旧状態の確認、JSON の読み込み、操作ごとの現行鍵の読み込み・初回生成、暗号処理、保存・バックアップ除去まで保持する。読み取りも参加し、ローテーション途中の異なる世代の組み合わせを観測させない。
- 単調時計で最大5秒を管理し、競合時だけ `Atomics.wait` で最大10 msずつ待つ。非競合の取得エラーは即座に原因を保持して返す。
- 本体の成功・例外にかかわらず `finally` で非再帰 `rmdirSync` を使う。解放失敗は成功として返さず、本体も失敗した場合は `AggregateError` で両原因を残す。
- 時刻・PID を根拠に残存ロックを削除しない。所有者の停止確認とロック削除の間に別の所有者が生じる回収競合や、停止中の正当な所有者からの強奪を避ける。異常終了後の操作は安全側に期限切れで失敗する。
- 初回鍵生成を含め、同じディレクトリ内の一意な一時ファイルを `openSync(..., 'wx', 0o600)` で作成する。fd で書き込み・権限設定・close してから rename し、取得していない一時ファイルは削除しない。既存の旧 `.tmp` も保持する。

二つのファイルの rename は永続的な単一トランザクションではない。ローテーション中断時の `master.key.bak` による更新拒否と、全プロセス停止・隔離コピー上での全値検証・復元・残存ロック除去を組み合わせる。利用者向け手順は英日 README に記載する。

実プロセスの回帰は IPC で開始を揃え、ファイル通知で保存段階への到達とロック競合の発生を確認する。SIGKILL の前に保持を確認し、テスト後は子プロセスを回収する。秘密の値にはダミーのみを使い、実ホームには触れない。

Node.js の [ファイルシステム API](https://nodejs.org/api/fs.html) に従い、`wx` の既存パス・symlink への排他性を使う。ローカルファイルシステムで同じ規約に従うプロセスを対象とし、旧版との同時更新・直接編集・分散/NFS・電源断のトランザクション保証は対象外とする。
